# Support

Use [GitHub Issues](https://github.com/CruxExperts/BestBackup/issues) for bugs and feature requests. Identify whether you are using the retained 1.x commands or the `bbackup production` interface.

For a bug report, include the bbackup version, Linux distribution, Python version, command, storage type, and a short description of the expected and observed behavior. Remove passwords, access keys, repository URLs with credentials, personal data, and sensitive file paths before posting configuration or output. Never attach host bindings or credential files.

Version 2.0.7 includes documentation and release-readiness updates plus targeted build-tool security maintenance. It makes no production runtime changes or new qualification. Support remains limited to the documented tested paths, including the bounded user-level scheduled file-backup guest drills; see the [authoritative qualification record](docs/development/version-2.md). B2/AWS provider protection and independent host-loss recovery remain unqualified. For development builds, include the commit and policy schema version.

For a security vulnerability, do not open a public issue. Follow the private process in [SECURITY.md](SECURITY.md).
